The callback stays pure and worker-safe (no DOM, no postMessage, no React); the Phase 4 worker wraps it. This plan is the foundation the worker (04-03), the progress overlay (04-04), and the page wiring (04-06) all consume.

Purpose: without a progress signal the parser, the worker has nothing to relay and the UI has nothing to render. This is the lowest-layer, dependency-free change (Wave 1).

Output: `parseStaad` extended + `ParseProgress` exported + unit coverage proving both non-breaking compatibility and correct progress fraction sequence.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| parseStaad onProgress → caller | A numeric fraction [0,1] crosses from the pure parser to whoever provides the callback (worker/main thread) |
| input text (untrusted `.std`) → parse | The progress callback is driven by input-derived structure (block count), but the fraction is always a computed number |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 | DoS | Size-guard bypass via callback | mitigate | The 64 MB `MAX_INPUT_LENGTH` early return stays BEFORE any onProgress invocation (T-04-01 preserved); oversized input never allocates/tokenizes or reports progress |
| T-04-02 | Tampering | Callback invoked with non-[0,1] / non-monotonic fraction | mitigate | Fractions are hard-coded (0.1, block-interpolated 0.15→0.95, 1.0) from block count — never derived from input strings; test B asserts non-decreasing + final 1.0 |
| T-04-03 | Tampering | Parser captures DOM/postMessage/React in the callback | mitigate | The callback is a pure value function; the parser never references postMessage/DOM/React — the worker wraps it (04-03). Only a numeric argument is passed |
| T-04-04 | DoS | Callback spam on huge block counts | mitigate | Cadence is per-block (hundreds-thousands, not millions); a 1-2% delta throttle may be added in the worker (04-03), not here |
| T-04-SC | Tampering | npm installs | mitigate | None — this plan only edits parser source + tests, no new dependencies |
</threat_model>
