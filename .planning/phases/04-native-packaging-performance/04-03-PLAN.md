<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted `.std` text → postMessage → worker | Up to 64 MB string structured-clones into the worker; the parser (already tolerant) runs on it |
| worker → main (progress / result) | Structured-cloned ParseResult (Maps) crosses back; fraction numbers cross as progress |
| worker singleton → lifecycle | A module-level Worker reused across opens |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-10 | DoS | Worker parse of huge input blocks main thread indirectly | mitigate | 64 MB `MAX_INPUT_LENGTH` cap (parser) bounds the largest clone; structured clone is one O(model) copy at result time, not per-frame (RESEARCH §5.2) |
| T-04-11 | Tampering | Raw/typed message confusion | mitigate | Discriminated union on `type`; worker ignores non-`parse`; main handler ignores unknown types; every message checked before cast |
| T-04-12 | Tampering | Untrusted result content | mitigate | result is a typed `ParseResult` fed through the SAME `setModel` commit path (04-06) — no new rendering trust boundary |
| T-04-13 | DoS | Worker message spam | mitigate | ≥1% fraction-delta throttle in the worker post() (per-block cadence bounded) |
| T-04-14 | Tampering | Worker singleton stuck after error | mitigate | `worker.onerror` nulls the singleton so the next open re-creates it |
| T-04-15 | Tampering | Static worker path bypass (R-1 Turbopack regression) | mitigate | URL literal enforced; R-1 verification + webpack fallback live in 04-06 build task |
| T-04-SC | Tampering | npm installs | mitigate | No new deps (raw postMessage, no Comlink) — matches parser zero-dependency philosophy |
</threat_model>
