<objective>
Build the tokenizer — the grammar layer that turns raw `.std` text into structured entries the parser can consume.

Purpose: `.std` is free-format (PITFALLS.md P2): `;` packs multiple entries per line, lines continue with a trailing `" -"`, `*` lines are comments, tokens are space-separated (never comma), quoted section-DB names contain spaces, and STAAD writes trailing-dot floats. A naive line parser fails on real GUI files — this is the single most reused primitive in the phase.

Output: `tokenize(text): TokenizedLine[]` with per-entry line numbers, ready for block segmentation (01-04) and command handlers.
</objective>

<feature>
  <name>Tokenizer</name>
  <files>packages/parser/src/tokenizer.ts, packages/parser/test/tokenizer.test.ts</files>
  <behavior>
    Input: raw .std text. Output: TokenizedLine[] where each TokenizedLine = { line: number (1-based original source line), tokens: string[] } and each physical input line may yield one or more entries (semicolon-split), each an entry line.

    Cases:
    - CRLF and LF line endings both split correctly → same entry count
    - Lines whose first non-blank char is `*` are comments → omitted entirely
    - `;` splits multiple entries on one physical line → 1 physical line yields N entry lines, all sharing the original line number
    - A line ending with a space followed by `-` (continuation) joins the NEXT physical line into the same entry → entry tokens are the concatenation of both physical lines, minus the trailing `-`
    - Tokens are split on whitespace, never commas; `1, 2, 3` stays as fewer/larger tokens (commas are data, not separators)
    - Quoted tokens `'EUROPE (EN 2023).DB3'` and `'IPE 300'` are preserved as single tokens including inner spaces; quotes are stripped, and the token is tagged quoted=true
    - `1.` `0.` `1E3` `1.0E-03` `-2.8` are preserved as literal token strings (numbers are parsed by handlers, not here)
    - Command abbreviations are NOT expanded here (that is canonicalize's job in 01-04)
    - Empty lines are dropped
  </behavior>
  <implementation>Hand-written character scanner — NOT regex-based (PITFALLS.md security: regex-heavy tokenizers on untrusted input risk ReDoS; hand-written state machine is the documented mitigation). Scan char by char: track current physical line number; accumulate tokens on whitespace boundaries; treat single-quote as quoting start (consume until closing quote, strip quotes, mark quoted); when a token equals `-` as the LAST token of a physical line, set continuation flag and merge next physical line into the current entry. Semicolon terminates the current entry and starts the next within the same physical line. Skip `*` comment lines at line start (first non-blank char). Export types Token { text: string, quoted: boolean } and TokenizedLine { line: number, tokens: Token[] } — entries, not physical lines, are the unit so semicolon-packed lines become multiple TokenizedLines sharing line numbers. No numeric parsing, no DOM/global access (worker-ready).</implementation>
</feature>
