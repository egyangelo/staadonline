# Phase 2 — UI Design Contract (File Opening & 3D Rendering)

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
> Design direction: Apple-style fluid interface (user-requested "smooth apple-like look and feel") — translucent floating chrome, size-specific tracking, interruptible velocity-aware springs.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — **manual tokens** |
| Preset | not applicable |
| Component library | none (hand-rolled CSS Modules; `drei` `OrbitControls` is the only third-party interactive component) |
| Icon library | none — text-first controls; up to 2 inline SVG glyphs allowed (folder-open on the Open control, chevron on the stats toggle). No icon dependency. |
| Font | `system-ui` stack (Apple §15: default to system font — optical sizing + tracking come free). Replaces the current Arial/Helvetica globals.css stack. Mono variant (`ui-monospace, "Cascadia Mono", Consolas, monospace`) permitted for file names, bounds, units — inherits 14px, no new weight/size. |

**Why no shadcn:** `web/components.json` does not exist, there is no tailwind.config/postcss.config, and the stack is Next.js 16 + React 19 + R3F/three 0.185 with a deliberately minimal floating overlay (D-12). Initializing shadcn would add a Radix/Tailwind layer to a canvas-first, gesture-heavy 3D surface where almost no conventional DOM behavior is needed, and no preset is available (interactive-only). Manual CSS Modules tokens are the lower-risk, phase-appropriate choice. Skipping `npx shadcn init` (no preset; interactive). Registry safety gate: not applicable.

### Existing Styling to Preserve / Fold In (catalog — do not re-specify)

- `web/app/globals.css` — CSS custom properties `--background`/`--foreground` + `prefers-color-scheme` dark toggle, `-webkit-font-smoothing: antialiased`, `box-sizing` reset. **Keep**; extend with viewer tokens; change font-family to the `system-ui` stack.
- `web/app/page.module.css` — the old home-page layout. The page becomes the viewer (D-11), so most of this is refactored away. **Carry over only:** the stats-grid card pattern (`grid`, `cardValue`/`cardLabel`), the uppercase-12px label style, the mono `details` block, and the error/warnings/clean color families — into the new viewer CSS module.
- `web/app/layout.tsx` — keep as-is (metadata only).

## Typography

Exactly 4 sizes, exactly 2 weights. Size-specific tracking (Apple §15 — never one value for all sizes). Line-height tracks size inversely: tight on headings, loose on body.

| Role | Size | Weight | Line Height | Tracking | Usage |
|------|------|--------|-------------|----------|-------|
| Caption | 12px | 400 | 1.4 | +0.06em | Uppercase labels ("SIZE EXAGGERATION", "UNITS"), unit hints, stat-card field labels |
| Detail | 14px | 400 | 1.5 | +0.01em | Slider value readout ("15×"), file name, stats values, bounds, secondary body copy |
| Body | 16px | 400 | 1.5 | 0 | Empty-state body, error body, button labels (Open control = 16px 600), toast body |
| Heading | 24px | 600 | 1.15 | −0.018em | Empty-state heading ("No model loaded"), stats value emphasis, panel titles |

- Mono variant: `ui-monospace, "Cascadia Mono", Consolas, monospace` at 14px / 400 / 1.5 for file names, bounds, and units only.
- Vibrancy rule over translucent chrome (Apple §12/§15): over blurred surfaces, bump weight to 600 and tracking by +0.01em relative to the row above; do not use flat gray text on translucent glass.
- Respect user text-size: layout spacing in `rem` where practical (font-size in px per contract; spacing tokens remain fixed).

| Primary text | `#1D1D1F` | `#F5F5F7` | Body, headings, stats values |
| Secondary text | `#6E6E73` | `#A1A1A6` | Captions, labels, mono details, error body |
| Destructive | `#FF3B30` | `#FF453A` | Error toast border + error title only (no destructive buttons in this phase) |

| Dropzone drag-over fill | `rgba(0,122,255,0.12)` | `rgba(10,132,255,0.16)` | Window-wide highlight when a file is dragged over the app |

**Accent reserved for (the complete list — never expand to "all interactive elements"):**

1. **Primary CTA `Open STAAD File` button fill** (`#007AFF` light / `#0A84FF` dark), label `#FFFFFF` always.
2. **Drag-over indicator**: the 2px dashed accent ring + drag-over fill around the dropzone in the empty state; once a model is loaded, a transient accent ring (2px, radius 24px, glow `0 0 0 1px` accent at 60% opacity) telegraphing "drop to replace".
3. **Exaggeration slider**: filled track + thumb (`#007AFF` / `#0A84FF`; thumb 20px, white inner dot).
4. **Keyboard focus ring**: 2px accent ring, 2px offset, radius 12px on overlay controls.

Everything else stays neutral: secondary buttons/links are neutral secondary-text color, never accent; slider label and value readout are primary/secondary text, never accent (accent reserved for the track/thumb); stats values are one of `#1D1D1F`/`#F5F5F7` by weight, not accent; error copy uses destructive red, not accent.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **Open STAAD File** — the only secondary note directly beneath: "or drag a .std file onto the window" (14px, secondary text) |
| Empty state heading | **No model loaded** |
| Empty state body | Open a `.std` STAAD input deck to see its analytical model in 3D. Parsing happens entirely in your browser — nothing is uploaded. |
| Empty state next step | **Use "Open STAAD File", or drag a .std file onto this window.** |
| Loading state | **Opening…** (16px, secondary text, spinner; overlay blocks input, cancel-safe — window-level drop aborts cleanly) |
| Loaded status | **Loaded** (success chip) · file name in mono · clean note "Clean parse — no warnings." only when zero warnings |
| Error — wrong type | **Not a STAAD file** — This file isn't a `.std` input deck. Choose a `.std` file and try again. |
| Error — oversized/unreadable | **File too large or unreadable** — STAAD Online reads `.std` decks up to 64 MB. Choose a valid, smaller file and try again. (FILE-04; fires before parsing, per parser `MAX_INPUT_LENGTH = 64_000_000`) |
| Approximate sections chip | **N approximate** — "N" = count of sections resolved to nearest-shape fallbacks (`UNRESOLVED_SECTION` / `approximate` flag, D-07). Clicking is Phase 3 (INSP-03); chip is informational-only in Phase 2. |
| Destructive confirmation | **None in Phase 2.** Loading a new file replaces the current model non-destructively (scene is derived data; no confirmation dialog — Apple §16 Agency). Picker cancel leaves state untouched (FILE-03). Repeat-open during LOADING aborts the in-flight open and is safe. |

Primacy: the empty state's only action is the accent CTA. After load, the Open control remains the single visible action; the stats card is informational and collapses.

## Motion & Visuals (Apple-style, from apple-design skill)

Springs throughout — no pre-scripted duration clips for anything a user can touch; every animation is interruptible and animates **from the live on-screen value** (Apple §3 — read presentation value on interrupt, never the target value).

| Interaction | Damping | Response | Notes |
|-------------|---------|----------|-------|
| Overlay chrome enter/exit | 1.0 | 0.35s | Translates up 8px → 0 on enter, down 8px on exit (same axis, §7). **Materialize, don't fade** (§12): animate `backdrop-filter` blur 0→20px + scale 0.98→1 + opacity together so the glass reads as a real surface arriving. |
| Slider thumb + value | 1.0 | 0.30s | Continuous 1:1 tracking through the whole gesture; spring covers only the final settle. |
| Empty-state dropzone hover | 1.0 | 0.25s | Scale 1.00→1.02, border-color→accent; feedback on pointer-**down** (scale 0.97) not on release. |
| Camera settle (gesture release) | 0.8 | 0.40s | Momentum spring — bounce only because a flick/orbit preceded it (§4). `OrbitControls` `enableDamping` carries the finger's release velocity with no visible seam (§5, §6 — drei handles velocity handoff natively). |
| Model appear (scene→canvas) | 1.0 | 0.40s | Cross-dissolve the loaded scene in over the loading state; no rotate/slide. |
| Drag-over ring (drop-to-replace) | 1.0 | 0.35s | Accent ring scales from the current overlay ring outward toward the canvas edge (§8), telegraphing the replace outcome. |

Rules applied:
- **Interruptibility:** controls are never locked during a transition; a grabbed overlay mid-flight is re-targeted from its current transform (§3). 2D motion decomposes into independent X and Y springs.
- **Velocity handoff:** on gesture release we hand the spring the pointer velocity (relative form `v/(target−current)` if the spring API needs normalized velocity; `drei`/OrbitControls consumes absolute px/s — pass raw there).
- **Frame smoothness (§11):** animate only `transform` + `opacity` (+ `backdrop-filter`, compositor-favorable with a hardware-accelerated `will-change: transform, opacity, backdrop-filter` on the chrome); no full-viewport moving background — the scene is a static model, camera motion only.
- **Spatial consistency (§7):** chrome anchors bottom-left cluster (Open + slider), StatsSummary bottom-left above it, error toast bottom-center; every surface enters/exits along the same axis it came from.
- **Translucency hierarchy (§12, D-12):** only one floating layer is translucent at a time over the canvas — never stack a light translucent surface on another; the stats card gets a heavier shadow (`0 16px 48px rgba(0,0,0,0.16)`) than the toolbar cluster (`0 8px 32px rgba(0,0,0,0.12)`) because it is the larger surface.
- **Rubber-banding (§9):** OrbitControls min/max distance plus damping produce the soft-stop boundary feel; the slider clamps 1–100 with the same damping.

### Reduced Motion & Accessibility (Apple §14)

Three independent signals, baked into the components:

```css
@media (prefers-reduced-motion: reduce) {
  /* Springs → short opacity cross-fades / static settle. Drop elastic/overshoot. */
  .viewport-chrome { transition: opacity 150ms ease; transform: none !important; }
  .exaggeration-slider .thumb { transition: none; }
  .stats-card { transition: opacity 150ms ease; }
}
@media (prefers-reduced-transparency: reduce) {
  /* Frostier / solid chrome: raise background alpha, drop blur. */
  .viewport-chrome, .stats-card { background: #FFFFFF; backdrop-filter: none; }      /* light */
  .viewport-chrome, .stats-card { background: #1C1C1E; backdrop-filter: none; }     /* dark */
}
@media (prefers-contrast: more) {
  /* Near-solid backgrounds + defined contrasting 1px border on all floating surfaces. */
  .viewport-chrome, .stats-card { border: 1px solid #9A9AA0; }
}
```

- Reduced-motion keeps opacity/color feedback (status chips, error) — reduced motion ≠ no feedback.
- No loops near 0.2 Hz, no full-viewport moving backgrounds, abrupt dark↔light theme changes eased where cheap. Large moving objects (whole model during auto-fit) stay opaque but camera travel is damped; auto-fit in reduced-motion jumps in one frame instead of flying.
- Orbits during drag: never dim the whole model while orbiting; only Firefox-scale `renderer.localClippingEnabled` concerns are handled by the executor (Phase 2 camera is the only motion).
