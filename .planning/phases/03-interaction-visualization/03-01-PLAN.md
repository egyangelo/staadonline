## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| modelStore members/keys (untrusted `.std`-derived strings) → colorMode assignment | Section/group/material strings from parsed files become palette lookup keys |
| colorLayer buffer write → GPU | Per-instance colors cross into WebGL as a Float32 attribute |
| viewerStore prefs → all chrome/scene | Committed interaction prefs are consumed app-wide |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Tampering | Prototype pollution via section/group/material keys | mitigate | first-seen key→index stored in a real `Map`, never a plain object (keys are file-derived, `__proto__`-style strings must not pollute) |
| T-03-02 | Tampering | Palette string injection | mitigate | palette is a fixed in-code 8-element array; only its index is derived from file data; no file string is ever interpreted as a color |
| T-03-03 | DoS | Unbounded palette/cache growth | mitigate | cache keyed by mode+theme (bounded at 8 palettes), assignment map bounded by distinct keys ≤ members count; no array indexed by member input directly |
| T-03-04 | Tampering | Store corruption via setter misuse | mitigate | one-key atomic zustand `set` per action; `selectedKind` constrained to a `'member'\|'support'` union so consumers never render ambiguous data |
| T-03-05 | Information Disclosure | Model content in colors | mitigate | colors are a fixed palette — no data exfiltration vector exists (local-only, consistent with privacy positioning) |
| T-03-SC | Tampering | npm installs | mitigate | No installs — this plan and all of Phase 3 reuse the Phase 2 pinned stack (three 0.185.1, fiber 9.7.0, drei 10.7.8, zustand 5.0.15) |
</threat_model>
